## トークンを抑える運用

1. **1会話 = 1範囲の1段階**。段階が終わったら私が「/clear してから『動画計画の範囲N の段階B から』」と言うので、`/clear` を打ってそれを送ってください。会話の引き継ぎは本ファイルと `range<N>.md`、メモリだけで足りるようにしてある。
2. **モデルは私がサブエージェントの model 指定で自動で切り替える**(A と C は Sonnet 5.5、B は Opus 5.5)。`/model` は不要。メインの会話は段取りと報告だけにする。
3. **画像は見るものだけ**: 一覧画像(1枚 30 コマ)を 1〜2 枚 → 欲しい時刻のフレーム原寸を 6〜10 枚。範囲全体の一覧を毎回見直さない(時刻表があるので)。
4. **コードは範囲だけ読む**: `grep -n` で位置を探し、`sed -n` で該当部分だけ。190 KB の `ds_tdl_world_bazaar.py` などを丸ごと読まない。新しい範囲は新規ファイルで作り、既存の大きなファイルには差し込みだけ。
5. **ログは tail**、確認は数値(三角形数・フットプリントの重なり・落下なし)+縮小画像 1〜2 枚。
6. 写真集め・Web 調べが要るときは Sonnet のサブエージェントに「要点と保存先だけ」報告させる。
7. 範囲の終わりに commit + push + 本番確認を**毎回**やる(1範囲 = 1コミット。大きい範囲 1・2・5・6・7 は途中で A と B の区切りでもコミットしてよい)。

## 守ること

- **木・ヤシ・鉢の木・丸い刈り込みも作る(2026-10-04 ユーザー指示で解禁)。** 過去に無効化した箇所(export_mock.py の trees3d・shrubs3d、mock_template.html の woods()、PZ_Trunk/PZ_Canopy、palm() 呼び出し)は復活・再利用する。夜景は作らない。v1 の電飾は形の参考にするだけ。
- 動画フレームはテクスチャに貼らない、リポジトリに入れない。色は塗り(材質の色)で合わせる。YouTube Shorts は使わない。
- ユーザーの写真(`images/`)があればそちらを優先。動画は「写真のない部分」と「配置・寸法の確認」に使う。
- 動画は魚眼で端が歪む。長さ・高さは OSM の外形と、既存モデルの寸法(窓の高さ 1.2 m、1階 3〜4.3 m など)で確かめ、フレームから目分量で決めない。
- 別タブの未コミット変更(`tools/organize_frames.py` など)は勝手にコミット・破棄しない。
