## フェーズ6でやったこと

つなぎ目の修正・Playwright で駅→城の散歩確認・圧縮・README・本番反映。

- **WB出口〜プラザ地面〜城フォアコートの境目**: 高さ・隙間・Zファイティングとも問題なし(元々 `ds_tdl_plaza_ground.py` が `cinderella`/`tdl_world_bazaar` の実フットプリントを切り抜いているため)。
- **既知の問題だったハブ西(トゥモローランド方向)の約1.5mの段差の壁の原因**: 地面の高さそのものがずれていたのではなく、**ハブ西の池をまたぐ歩行者用の橋(OSM way 1283322088、`highway=pedestrian`/`bridge=yes`/`area=yes`、x -525.0〜-482.1、y 658.7〜678.0)が丸ごと穴になっていた**ことが原因。調査の経緯:
  1. `ds_tdl_plaza_ground.Terrain` と `ds_ground.Terrain`(tdl_land_ground)を実際に構築して境目(旧 CLIP 西端 x=-495)の高さを比べたが、差は最大でも 0.4m 程度で 1.5m には届かなかった。
  2. `tdl_plaza_ground.json` と `tdl_land_ground.json` の実三角形を読み(`ds_tdl_plaza_hub.Surface` を流用)、ハブからトゥモローランドの門 (-509, 663.5) へ向かう実際の経路上で高さを追ったところ、x 約 -493〜-501(旧 CLIP のすぐ内側〜外側)で **両方のモデルとも三角形が全く無い**区間(約8m)が見つかった。
  3. その区間の座標を調べると、OSM の橋ポリゴン 1283322088(`layer=1`)の上だった。この橋は `tdl_water`(ランドの水面モデル、フェーズ3以前に別タブで作成済み)の実フットプリント(池)とほぼ重なっている。`ds_tdl_plaza_ground.py` は「橋は池の上でも舗装のまま残す」処理(`water.difference(bridge)`)を池の OSM タグ分にしか適用しておらず、`tdl_water` モデルの実フットプリント(`CUT_MODELS` の `blocked` に含まれる)には適用していなかったため、CLIP 内側の橋の一部まで切り抜かれていた。CLIP の外側(旧西端 -495 より西)は `ds_ground.py` 側の `on_ground()` が `layer=1` を「地面ではない(高架)」として最初から除外するため、そもそも橋が作られていなかった。橋の実面積(430m²)のうち CLIP 内は数m²しかなく、結果として橋の大部分(幅にして約35m)が完全な空白になっていた。落ちた先は池の水底(`WS_bed`、z 約 -2.7m)で、そこから舗装(z 約 -0.9m)へ登ろうとすると 1.5m 超の段差として壁扱いになる ── これが「1.5mの段差の壁」の正体と判断(水面下に落ちてから登れない状態)。
  4. **直したこと**(`src/ds_tdl_plaza_ground.py`): (a) `CLIP` の西端を -495.0 → -530.0 に広げ、この橋をまるごと CLIP 内に収めた。(b) `plan()` で `tdl_water` の実フットプリントを `blocked`(建物と同列に無条件で切り抜く対象)から分離し、OSM の `water` タグと同様に `bridge` があれば残す扱いにした(`fill` 処理・花壇の除外にも同じ例外を反映)。(c) 地面の高さ計算(`Terrain` の `void`)は橋の有無に関わらず池全体を「穴」として扱ったまま(周りの陸地から補間)にして、橋の上の高さが池の水底の DEM 値を拾わないようにした(舗装の有無と高さ計算の穴判定を別変数に分離)。
